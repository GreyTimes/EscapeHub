Γενικές Οδηγίες Ανάπτυξης – Issues

Στόχος: Η δημιουργία μιας απλής αλλά λειτουργικής και playable έκδοσης του EscapeHub.

Γενικοί κανόνες
- Ακολουθούμε την υπάρχουσα δομή και αρχιτεκτονική του project.
- Ελέγχουμε αν μπορούμε να επαναχρησιμοποιήσουμε υπάρχουσες κλάσεις πριν δημιουργήσουμε νέες.
- Αποφεύγουμε περιττή πολυπλοκότητα και λειτουργίες που δεν ζητούνται στο issue.
- Χρησιμοποιούμε κατανοητά ονόματα και κρατάμε τον κώδικα απλό.

Backend & Frontend
- Η επιχειρησιακή λογική παραμένει στα Services και η επικοινωνία HTTP στους Controllers.
- Το Frontend επικοινωνεί με το Backend μέσω των υπαρχόντων API services.
- Προσθέτουμε βασικό έλεγχο εισόδων, χειρισμό σφαλμάτων και tests όπου χρειάζεται.
- Δεν αποθηκεύουμε μόνιμη πρόοδο παιχνιδιού αποκλειστικά στο Frontend.

Συνεργασία & Ολοκλήρωση
- Συνεννοούμαστε πριν αλλάξουμε κοινές κλάσεις ή υπάρχοντα API endpoints.
- Ελέγχουμε ότι οι αλλαγές μας δεν επηρεάζουν τη δουλειά των υπόλοιπων.
- Πριν ολοκληρώσουμε ένα issue, βεβαιωνόμαστε ότι το project κάνει build και τα σχετικά tests περνούν.

Όρια του project
Προτεραιότητα είναι να λειτουργούν σωστά οι βασικές λειτουργίες: ομάδες, επιλογή αποστολής, εξερεύνηση, στοιχεία, lobby και απλοί γρίφοι. Προηγμένες λειτουργίες όπως chat, WebSockets, real-time επικοινωνία και σύνθετοι μηχανισμοί γρίφων είναι εκτός scope.
Κριτήριο ολοκλήρωσης: Η ζητούμενη λειτουργία δουλεύει, έχει συνδεθεί σωστά με τα υπόλοιπα μέρη του project και δεν έχει προκαλέσει προβλήματα σε υπάρχουσες λειτουργίες.
