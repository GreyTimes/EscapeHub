## 1. Implementation
- [ ] Έχουν ικανοποιηθεί όλα τα κριτήρια
- [ ] Ο κώδικας ακολουθεί τη συμφωνημένη αρχιτεκτονική του έργου.
- [ ] Ο κώδικας είναι ευανάγνωστος και συντηρήσιμος.
- [ ] Δεν υπάρχουν περιττές τιμές ενσωματωμένες απευθείας στον κώδικα (hardcoded values).
- [ ] Έχει υλοποιηθεί διαχείριση σφαλμάτων όπου είναι απαραίτητο.
- [ ] Δεν έχουν συμπεριληφθεί (commit) ευαίσθητα δεδομένα, κωδικοί πρόσβασης ή κλειδιά API.

## 2. Testing
- [ ] Έχουν δημιουργηθεί ή ενημερωθεί test JUnit.
- [ ] Όλες οι σχετικές αυτοματοποιημένες δοκιμές περνούν επιτυχώς.
- [ ] To Gradle build ολοκληρώνεται επιτυχώς.
- [ ] Έχουν ληφθεί υπόψη ακραίες περιπτώσεις (edge cases).

## 3. Code Review
- [ ] Οι αλλαγές υποβάλλονται μέσω Pull Request.
- [ ] Τουλάχιστον ένα ακόμη μέλος της ομάδας ελέγχει το Pull Request.
- [ ] Τα σχόλια που προέκυψαν κατά τον έλεγχο έχουν διευθετηθεί.
- [ ] Δεν έχουν γίνει απευθείας commits στον κλάδο main.

## 4. CI
- [ ] Η ροή εργασίας (workflow) στο GitHub Actions ολοκληρώνεται επιτυχώς.
- [ ] Η στατική ανάλυση κώδικα ολοκληρώνεται επιτυχώς.

## 5. Documentation
- [ ] Το README έχει ενημερωθεί, εφόσον χρειάζεται.
- [ ] Η τεκμηρίωση του API έχει ενημερωθεί, εφόσον χρειάζεται.
- [ ] Το CHANGELOG έχει ενημερωθεί, όπου κρίνεται σκόπιμο.

## 6. Project Management
- [ ] Το Pull Request παραπέμπει στο σχετικό Issue.
- [ ] Έχει επαληθευτεί η ικανοποίηση των κριτηρίων αποδοχής του Issue.
- [ ] Ο πίνακας έργου (Project Board) στο GitHub έχει ενημερωθεί.
- [ ] Η χρήση AI έχει καταγραφεί, όπου εφαρμόζεται.

## Final Rule


Μια εργασία δεν θεωρείται «Ολοκληρωμένη» (Done) απλώς επειδή έχει γραφτεί ο κώδικάς της.

Πρέπει να έχει ελεγχθεί, να έχει περάσει από διαδικασία ελέγχου (review), να έχει ενσωματωθεί και να έχει τεκμηριωθεί, όπου αυτό είναι απαραίτητο.
